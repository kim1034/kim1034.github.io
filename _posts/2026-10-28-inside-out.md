## 한 줄 요약

**대화에서 드러나는 사용자 핵심 정보를 계층형 PersonaTree에 압축하고, 작은 모델이 기억을 지속적으로 편집하며, 큰 모델이 트리와 필요시 검색한 과거 대화를 이용해 개인화된 답변을 생성하는 방법이다.**

## Introduction

### 연구 배경

장기간 대화하는 AI는 사용자의 취향, 생활 습관, 성격과 그 변화를 기억해야 한다. 하지만 대화 기록은 계속 늘어나는 반면, 매번 모델에 넣을 수 있는 문맥의 길이에는 한계가 있다. 전체 기록을 반복해서 넣으면 비용이 증가하고, 오래된 정보나 관련 없는 대화가 현재 질문에 필요한 정보를 가릴 수도 있다.

이 논문은 영화 「인사이드 아웃」의 핵심 기억과 성격 섬에서 착안해, 사용자 이해에 중요한 정보를 구조적으로 유지하는 Inside Out 프레임워크를 제안한다.

### 기존 방법의 한계

- **고정 프로필:** 처음 작성한 사용자 속성만으로는 대화 중 드러나는 암묵적 특성이나 선호 변화를 반영하기 어렵다.
- **기억 조각의 누적:** 검색할 사실을 계속 추가하면 중복·상충하는 정보가 쌓일 수 있다. 무엇을 유지하고 고칠지에 대한 판단도 필요하다.
- **전체 대화 입력:** 모든 정보에 접근할 수 있어도 모델이 중요한 내용을 정확하게 활용한다는 보장은 없다.

이는 저자들이 제시한 문제의식이다. 모든 기존 검색 기반 기억 시스템이 갱신 기능을 갖지 않는다는 뜻은 아니다.

### 핵심 기여

1. 생물·심리·사회적 관점의 스키마에 따라 사용자 핵심 특성을 관리하는 **PersonaTree**.
2. 대화를 `ADD`, `UPDATE`, `DELETE`, `NO_OP` 작업으로 바꾸도록 학습한 **MemListener**.
3. 트리만 활용하는 빠른 경로와 과거 대화를 검색하는 경로를 결합한 **적응형 답변 생성**.

## Method

### 전체 구조

![Inside Out의 PersonaTree 구성, 학습 데이터 구축, MemListener 학습 및 추론 과정](/assets/images/inside-out/figure-1-framework.png)
*그림 1. 전체 프레임워크. 출처: 원 논문 Figure 1, PDF 3쪽.*

처리 흐름은 다음과 같다.

1. 사전 정의한 스키마로 초기 PersonaTree를 만든다.
2. 대화 기록을 시간순의 작은 묶음으로 나눈다.
3. MemListener가 최근 대화와 기존 트리를 읽고 기억 편집 작업을 생성한다.
4. 실행기가 경로·값·길이 제한을 검사한 뒤 트리를 갱신하고 버전을 저장한다.
5. 답변 모델이 사용자 질문과 트리를 읽는다. 상세 정보가 필요하면 원래 대화 기록도 검색한다.

### 수식 1: 기억 갱신과 답변 생성

![기억 트리 갱신 및 기억을 이용한 답변 생성 수식](/assets/images/inside-out/equation-1-state-generation.png)
*수식 1. 원 논문 §3.1의 식 (1)–(2). 사용자 제공 수식 이미지.*

첫 번째 식은 **기존 기억과 새 대화를 이용해 현재 기억을 만든다**는 뜻이다.

| 기호 | 의미 |
|---|---|
| `t` | 대화 묶음을 처리하는 시점 또는 단계 |
| `T_(t−1)` | 새 대화를 반영하기 전의 PersonaTree |
| `D_t` | 이번에 처리할 대화 묶음 |
| `f_update` | 편집 작업을 생성하고 실행해 기억을 갱신하는 함수 |
| `T_t` | 갱신을 마친 PersonaTree |

예를 들어 기존 기억이 “커피를 좋아함”이고 새 대화가 “요즘은 디카페인만 마심”이라면, 갱신 함수는 두 정보를 통합해 현재 트리를 만든다. 여기서 `f_update`는 트리 갱신 과정 전체를 나타내는 추상적인 함수이며, MemListener의 작업 생성과 실행기의 검증·적용을 포함해 이해할 수 있다.

두 번째 식은 **현재 질문, 현재 기억, 필요할 때 찾은 과거 대화를 함께 사용해 답변한다**는 뜻이다.

| 기호 | 의미 |
|---|---|
| `x_t` | 현재 사용자의 질문 또는 입력 |
| `H` | 전체 대화 이력 |
| `f_recall(T_t, H)` | 현재 기억을 단서로 대화 이력에서 관련 증거를 회상·검색하는 과정 |
| `f_gen` | 주어진 문맥으로 답변을 생성하는 함수 |
| `y_t` | 생성된 시스템 답변 |

식의 검색 함수에는 `T_t`와 `H`만 적혀 있지만, §3.4의 실제 검색 설명에서는 **현재 질문도 함께 사용해 검색 질의를 확장**한다. 빠른 경로에서는 별도 과거 대화 검색 없이 트리와 질문으로 답한다. 따라서 이 식을 매 질문마다 반드시 전체 이력을 검색한다는 뜻으로 해석하면 안 된다.

### 핵심 아이디어: 기억을 추가하는 것만큼 수정하는 것이 중요하다

아래는 논문의 동작을 설명하기 위한 예시이며, 원 논문의 실제 실험 사례는 아니다.

- 과거 대화: “나는 커피를 좋아해.”
- 최근 대화: “요즘은 잠 때문에 디카페인만 마셔.”
- 갱신된 기억: “커피를 좋아하지만, 수면 문제로 현재는 디카페인을 선호함.”

핵심은 서로 다른 시점의 발언을 단순 나열하지 않고, 현재 유효한 상태를 기존 정보와 통합하는 것이다. 반면 특정 날짜나 사건의 세부 내용은 압축 과정에서 빠질 수 있으므로 원본 대화 검색도 유지한다.

### 세부 방법 1: PersonaTree

PersonaTree는 사용자 특성을 계층적으로 정리한 외부 기억이다. 큰 틀은 **생물학적·심리적·사회적 측면**이며, Figure 1은 이를 신체적 특성, 심리적 특성, 성격적 특성, 인구통계적 특성, 행동적 특성 등으로 구체화한다.

잎 노드에는 숫자 벡터가 아니라 **설명 문장**을 저장한다. 예를 들어 생활 습관이나 선호를 사람이 읽을 수 있는 텍스트로 표현하는 방식이다. 사전에 정한 쓰기 범위와 잎별 길이 예산으로 기억의 구조와 용량을 통제한다. 확장 정책이 허용하는 경우에는 새 경로를 만들 수도 있다.

이 연구의 주된 방법은 계층형 기억 관리와 언어모델의 편집 정책이다. 트리라는 이유만으로 GNN 학습이나 일반적인 지식 그래프 추론 방법으로 분류하는 것은 적절하지 않다.

### 세부 방법 2: MemListener와 기억 편집

| 작업 | 역할 |
|---|---|
| `ADD(path, value)` | 아직 기록되지 않은 사용자 정보를 추가한다. |
| `UPDATE(path, value)` | 기존 잎의 문장을 새 문장으로 교체한다. 유효한 기존 정보와 새 정보를 통합해야 한다. |
| `DELETE(path, None)` | 더 이상 유효하지 않거나 명시적으로 제거해야 할 기억을 비운다. |
| `NO_OP()` | 현재 대화에 기억을 바꿀 만한 정보가 없으면 유지한다. |

정보 충돌을 어떻게 해결할지는 **작업 생성 모델**이 결정한다. 실행기는 허용된 경로와 값 형식, 길이 제한을 검사하며, 별도의 의미 판단으로 충돌을 해결하지 않는다. 따라서 형식이 올바른 작업이라도 내용이 틀릴 가능성은 남는다.

실제 사용 중에는 MemListener의 파라미터를 고정하고 외부 트리만 갱신한다. 새 대화가 생길 때마다 모델을 다시 학습하는 방식은 아니다.

### 세부 방법 3: SFT와 강화학습

DeepSeek-R1-0528을 이용해 대화와 기존 트리로부터 정답 편집 작업 및 갱신 상태를 합성하고, 수동 검증으로 잘못된 예시를 걸러 학습 데이터를 구성한다.

- **데이터 구성:** PersonaMem 약 15K와 HaluMem 약 13K.
- **SFT 단독 설정:** PersonaMem 15K로 학습한다.
- **SFT+RL 설정:** HaluMem 13K로 SFT 준비 학습을 하고 PersonaMem 0.5K를 강화학습에 사용한다.
- **학습 모델:** Qwen2.5-7B 및 Qwen3-8B 계열.
- **보상 평가:** Qwen3-32B의 추론 모드로 예측 작업과 기준 작업의 일치도를 평가한다.
- **최적화:** GRPO 계열의 DAPO를 사용하며, 입력당 8개 후보 작업 시퀀스를 생성한다.

논문은 이를 process-reward RL로 부르지만, 제시된 수식과 보상 프롬프트에서는 **작업 시퀀스 전체에 대한 점수**를 산출한다. 각 작업마다 독립적인 정답 보상을 주는 방식으로 설명해서는 안 된다.

#### 수식 2: SFT는 정답 작업을 따라 쓰도록 학습한다

![MemListener의 지도 미세조정에 사용하는 평균 음의 로그우도 손실](/assets/images/inside-out/equation-2-sft.png)
*수식 2. 원 논문 §3.3의 SFT 목적함수. 사용자 제공 수식 이미지.*

이 식은 **정답 편집 작업의 다음 토큰에 높은 확률을 주도록 학습하는 평균 음의 로그우도 손실**이다. 이 손실은 작아지는 방향으로 최적화한다.

| 기호 | 의미 |
|---|---|
| `θ` | 학습하는 MemListener의 파라미터 |
| `s` | 대화 묶음, 기존 트리, 갱신 규칙을 합친 입력 문맥 |
| `o_t` | 정답 편집 작업 시퀀스의 `t`번째 토큰 |
| `o_<t` | 그 토큰 앞에 있는 정답 토큰들 |
| `τ` | 정답 출력 시퀀스의 전체 토큰 수 |
| `P_θ(o_t ∣ o_<t, s)` | 입력과 앞선 정답 토큰이 주어졌을 때 다음 정답 토큰에 부여하는 확률 |

예를 들어 정답이 `UPDATE(preference.coffee, "현재는 디카페인을 선호함")`이라면 모델이 작업 이름, 경로, 값 등을 차례로 출력하도록 학습한다. 여기서 `o_t`는 `UPDATE` 작업 하나 전체가 아니라 **토큰화된 출력의 한 토큰**이다.

정답 토큰의 확률이 0.8이면 음의 로그값은 약 0.22이고, 0.1이면 약 2.30이다. 정답에 낮은 확률을 줄수록 손실이 커진다. 앞의 마이너스 기호는 로그확률을 최소화 가능한 손실로 바꾸며, `1/τ`는 출력 길이에 대해 평균을 낸다.

즉, SFT는 **주어진 정답 작업 시퀀스를 잘 재현하게 만드는 단계**다. 이 식만으로 그 기억이 실제로 옳거나 유용하다는 보장이 생기지는 않으며, 학습 기준 작업의 품질도 중요하다.

#### 수식 3: 강화학습은 더 좋은 작업 후보의 확률을 높인다

![DAPO 강화학습 목적함수, 동적 샘플링 조건, 중요도 확률비와 그룹 내 상대 이점](/assets/images/inside-out/equation-3-dapo.png)
*수식 3. 원 논문 §3.3의 RL 목적함수와 보조 식. 사용자 제공 수식 이미지.*

이 식의 목표는 **같은 입력에 대해 만든 여러 작업 후보를 비교하고, 상대적으로 좋은 후보는 더 자주 생성하도록 학습하되 한 번에 지나치게 크게 바뀌는 것을 억제하는 것**이다. 위 SFT 식이 최소화하는 손실인 반면, 여기의 `J_RL`은 최대화하는 목적함수다. 구현에서는 부호를 바꾼 손실을 최소화할 수 있다.

**기호를 먼저 구분하자.** 앞의 상태 수식에서 `y_t`는 시스템 답변이었지만, 이 RL 식의 `y_i`는 **학습 중 생성한 편집 작업 시퀀스 후보**다. 또한 여기의 `t`는 대화 갱신 단계가 아니라 후보 안의 토큰 위치다.

| 기호 | 의미 |
|---|---|
| `𝒟` | 학습 데이터셋. 앞의 새 대화 묶음 `D_t`와 다르다. |
| `s`, `y*` | 입력 문맥과 기준 정답 작업 시퀀스 |
| `G` | 같은 입력에서 생성하는 후보 수. 논문 설정은 8개다. |
| `y_i`, `∣y_i∣` | `i`번째 작업 후보와 그 토큰 길이 |
| `π_old` | 후보를 샘플링한 이전 정책 |
| `π_θ` | 현재 갱신 중인 정책 |
| `R_i` | 평가 모델이 해당 후보에 준 시퀀스 단위 보상. 범위는 −1부터 1이다. |
| `Â_(i,t)` | 후보 보상을 그룹 안에서 정규화한 상대 이점 |

**(a) 확률비 `r_(i,t)`는 해당 토큰을 얼마나 더 생성하려 하는지 나타낸다.**

분자는 현재 정책이 후보의 `t`번째 토큰에 주는 확률이고, 분모는 후보를 생성한 이전 정책의 확률이다. 두 확률 모두 같은 입력과 후보의 앞선 토큰들을 조건으로 한다.

- 확률비가 1이면 그 토큰의 생성 확률이 같다.
- 1보다 크면 현재 정책이 그 토큰을 더 생성하려 한다.
- 1보다 작으면 현재 정책이 그 토큰을 덜 생성하려 한다.

예를 들어 이전 확률이 0.20이고 현재 확률이 0.25라면 확률비는 1.25다. 이는 토큰 확률의 비율이며, 후보의 정답률이 25% 향상했다는 뜻은 아니다.

**(b) 상대 이점은 “같은 입력의 다른 후보보다 얼마나 좋은가?”를 나타낸다.**

`R_i`에서 후보 그룹의 평균 보상을 빼고 표준편차로 나눈다. 평균보다 보상이 높으면 양수, 낮으면 음수다. 예를 들어 평균이 0.4, 표준편차가 0.2일 때 보상 0.8인 후보의 상대 이점은 2이고, 보상 0.2인 후보는 −1이다.

목적함수를 최대화하면 일반적으로 양의 이점을 가진 후보의 토큰 확률은 높이고, 음의 이점을 가진 후보의 토큰 확률은 낮추는 방향으로 학습한다. 제시된 정의에서는 **시퀀스 하나의 보상으로 계산한 동일한 이점을 그 시퀀스의 여러 토큰에 사용한다.** 토큰마다 별도의 보상 모델이 점수를 주는 식은 아니다.

**(c) `clip`과 `min`은 유리한 방향의 지나친 확률 변화를 억제한다.**

논문은 하한 클리핑 계수 0.20, 상한 계수 0.28을 사용하므로, 클리핑된 확률비의 범위는 **0.80부터 1.28**이다. 원래 항과 클리핑한 항 중 작은 값을 선택해, 확률비를 과도하게 바꾸는 것만으로 목적함수를 계속 개선하지 못하게 한다.

예를 들어 상대 이점이 1인 후보에서 확률비를 1.50까지 높여도, 해당 항은 `min(1.50, 1.28)`인 1.28로 계산된다. 상한과 하한을 다르게 두는 비대칭 클리핑이 이 설정의 특징이다. 다만 이 식은 학습 유인을 조절하는 장치이며, 실제 모든 확률비가 항상 해당 범위 안에 있다는 강제 제약은 아니다.

**(d) 합과 정규화 항은 후보 전체의 토큰을 기준으로 평균을 낸다.**

바깥 합은 후보들을, 안쪽 합은 각 후보의 토큰들을 순회한다. 앞의 `1 / Σ_i ∣y_i∣`는 그룹의 전체 출력 토큰 수로 나누는 항이다. 후보별 평균을 먼저 낸 뒤 후보끼리 똑같이 평균내는 식과는 다르다. 기대값 `E`는 여러 학습 예시와 샘플링된 후보 그룹에 대한 평균적인 목표를 나타낸다.

**(e) 아래 제약은 모두 맞거나 모두 틀린 후보 그룹을 걸러내기 위한 것이다.**

`is_equivalent(y*, y_i)`를 만족하는 후보 수가 0보다 크고 `G`보다 작아야 한다. 즉, 정답과 동등한 후보가 적어도 하나는 있고, 그렇지 않은 후보도 적어도 하나는 있는 그룹을 요구한다. 이런 혼합 그룹을 확보하기 위해 동적 샘플링을 사용한다.

여기서 **정답 동등성 조건과 보상의 표준편차는 서로 다른 개념**이다. 보상은 연속값이므로 모두 오답이어도 점수는 서로 다를 수 있다. 다만 모든 후보의 보상이 같으면 상대 이점 식의 표준편차가 0이 되어 직접 정규화할 수 없으므로, 유효한 학습 신호를 얻기 위한 그룹 관리가 중요하다.

전체적으로 **SFT는 기준 작업을 모방하고, RL은 여러 후보의 상대적인 품질을 이용해 작업 생성 정책을 개선한다.** 이 학습 대상은 기억 편집 모델이며, 최종 사용자 답변 모델의 파라미터를 같은 식으로 갱신한다는 뜻은 아니다.

### 세부 방법 4: 두 가지 답변 경로

**빠른 경로**는 질문과 트리의 비어 있지 않은 기억만 넣어 한 번에 답한다. 사용자 취향처럼 핵심 상태만으로 답할 수 있는 질문에 적합하다.

**Agentic Recall 경로**는 질문과 트리를 바탕으로 검색 질의를 확장하고, 과거 대화에서 증거를 검색·재정렬한 뒤 질문·트리·검색 결과를 함께 사용한다. 세부 사건이나 긴 꼬리 정보가 필요한 경우를 보완한다.

실험에서는 트리만 사용하는 `PersonaTree`, 선택적으로 검색하는 `PersonaTree+Router`, 전체 검색·융합 경로를 사용하는 `PersonaTree-ALL`을 구분한다.

## Experiments

### 실험 설정

- **평가 데이터셋:** PersonaMem. 사용자별 기록은 약 10개의 다중 턴 대화를 시간순으로 연결하며, 문맥 길이는 약 32K 토큰이다.
- **태스크:** 15종의 개인화 과제를 포함하며, 결과를 사실 회상·선호에 맞는 추천·새 아이디어·선호 변화의 이유·선호 변화 추적·새 상황 일반화·사용자 언급 정보 회상 등 7가지 능력별로 분석한다.
- **비교 방법:** Only LLM, ALL Dialogue, LangMem, Mem0, A-Mem, MemoryOS.
- **평가 지표:** 선택형 질문의 정확도. Overall 및 능력별 정확도를 보고하며 높을수록 좋다.
- **답변 모델:** DeepSeek-V3.1, Longcat-Flash-Chat, DeepSeek-R1-0528.
- **검색 설정:** BGE-M3, BGE-Reranker-Large, 검색 개수 4. 비교 방법 간 검색 문맥 길이를 대체로 일치시킨다.

### Ablation Study

**1. 검색의 기여가 크다.** Qwen3-8B-RL로 기억을 관리하고 DeepSeek-R1-0528로 답할 때, Table 1의 Overall은 다음과 같다.

| 추론 구성 | 정확도(%) |
|---|---:|
| 트리만 사용 | 65.70 |
| 트리 + Router | 74.19 |
| PersonaTree-ALL | 76.06 |

따라서 76.06%라는 결과를 트리 압축만의 효과로 해석하면 안 된다. 상세 대화 검색과 융합이 최종 성능의 중요한 부분이다.

**2. 작은 기억 모델도 학습을 통해 개선된다.**

![여러 기억 편집 모델의 학습 전후 성능과 평균 기억 문맥 길이](/assets/images/inside-out/table-2-memory-training.png)

DeepSeek-R1-0528을 답변 모델로 사용하면, Qwen3-8B의 기억을 이용한 정확도는 학습 전 47.71%, SFT 후 63.33%, SFT+RL 후 65.70%이다.

Table 2는 편집 작업의 직접적인 정답률이 아니라, **각 모델이 만든 트리를 사용했을 때의 후속 질의 정확도**를 보고한다. 또한 SFT 단독과 SFT+RL의 학습 데이터 구성이 다르므로 차이를 강화학습 알고리즘만의 효과로 단정하기 어렵다.

학습된 Qwen3-8B의 평균 기억 문맥은 약 2,348 토큰으로, 전체 대화 약 32K 토큰보다 짧다. 이 수치는 트리 기반 기억 문맥의 길이이며, 전체 시스템의 학습비·갱신비·검색비까지 약 13.6배 감소했다는 뜻은 아니다.

## Conclusion

Inside Out은 장기 개인화 대화에서 기억을 계속 누적하기보다, **사용자의 핵심 상태를 구조적으로 유지하고 갱신하는 문제**에 초점을 맞춘다. 작은 모델이 외부 기억을 관리하고 큰 모델이 응답을 생성하는 역할 분담을 제안하며, 상세 정보는 과거 대화 검색으로 보완한다.

저자들은 스키마의 적용 범위, 시간·출처·다중 버전 정보 표현, 개인정보 관리 기능을 후속 확장 과제로 제시한다. 지속적인 대화 스트림을 목표로 하지만, 실제 검증은 유한한 PersonaMem 기록을 이용하므로 무한 기간의 안정성을 입증한 것은 아니다.

## 나의 생각

아래 내용은 원 논문의 실험 결과와 구분되는 리뷰 관점의 해석이다.

### 좋았던 점

- 기억의 양뿐 아니라 현재 유효한 상태를 유지하는 편집 능력에 초점을 맞춘 점이 실용적이다.
- 트리가 사람이 읽을 수 있는 문장이므로, 무엇을 기억하는지 점검하기 쉽다.
- 핵심 특성을 압축하면서 상세 기록 검색을 유지해 압축으로 인한 정보 손실을 보완한다.

### 아쉬운 점과 질문

- **평가 범위:** 선택형 정확도가 실제 자유 대화의 만족도, 자연스러움, 관계의 지속성을 얼마나 반영하는지 추가 검증이 필요하다.
- **오류의 누적:** 잘못된 편집이 핵심 프로필에 들어갔을 때, 이후 여러 답변으로 전파되는 문제를 어떻게 발견하고 회복할 수 있을까?
- **스키마 편향:** 정해진 심리·사회적 분류가 모든 사용자와 문화적 맥락을 충분히 표현할 수 있을까?
- **보상과 데이터 구성:** 작업의 기준 답안과 LLM 평가자의 판단에 의존한다. 동일한 데이터 조건에서 SFT와 RL을 비교하면 효과가 어떻게 달라질지도 궁금하다.
- **출처와 삭제:** 트리의 기억을 수정하거나 삭제하는 것과 원본 대화 및 과거 버전의 정보를 삭제하는 것은 별개다. 실제 배포에서는 이를 함께 설계해야 한다.

### 적용 아이디어

논문 추천 도우미에 적용한다면 사용자의 관심 주제, 선호하는 설명 깊이, 현재 연구 과제를 작은 트리로 관리할 수 있다. 반면 개별 논문을 언제 읽었는지, 어떤 문장에서 질문했는지 같은 상세 기록은 별도로 두고 필요할 때 검색한다.

새 대화가 기존 선호를 보완하는지, 현재 상태를 바꾸는지, 일시적인 요청인지 구분하는 것이 중요한 설계 지점이다. 이 적용안은 본 논문에서 직접 검증한 응용 결과는 아니다.
